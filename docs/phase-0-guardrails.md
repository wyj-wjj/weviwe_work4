# 阶段 0 实施护栏

## 不可妥协约束

1. MySQL 是唯一权威数据源，账号、权限、内容、版本、测验题和未命中问题都以 MySQL 为准。
2. Milvus 只作为向量检索索引，不保存或返回权威正文。
3. 权限校验以后端为准，前端隐藏入口不能替代接口和服务层过滤。
4. 未命中时模型不得自由回答，只能返回固定提示并记录未命中问题。
5. MVP 不引入复杂中间件，包括 LangChain、LangGraph、Celery、Redis、Kubernetes、微服务和对象存储。

## 后端测试策略

- 服务单元测试：覆盖权限过滤、内容发布、版本管理、索引失败、AI 未命中、来源一致性和不持久化测验提交。
- API 测试：覆盖登录、管理员后台权限、员工权限过滤、内容详情、测验题、RAG 成功回答和无泄露错误响应。
- 迁移检查：后续数据模型阶段验证表结构、约束、升级和回滚。
- 集成风格测试：使用假 DashScope 客户端和假 Milvus 客户端验证索引失败、重试和来源一致性，不调用真实 DashScope。

## 前端测试策略

- 路由守卫测试：覆盖员工登录、管理员登录、后台路由限制、未认证跳转和非管理员访问后台。
- 状态仓库测试：覆盖 token、用户身份、账号类型、内容权限级别和退出登录。
- API 错误处理测试：覆盖认证错误、权限错误、服务异常和 AI 服务不可用。
- 页面状态测试：覆盖通用用户可见性、完整权限用户可见性、空状态、加载状态和 AI 未命中界面。
- Playwright 冒烟测试：覆盖管理员发布、通用用户隔离、完整权限用户可见、AI 未命中和测验不持久化。

## 外部服务测试边界

- 自动化测试必须使用假 DashScope 客户端和假 Milvus 客户端。
- 常规测试不得调用真实 DashScope，不得依赖真实 Milvus 数据。
- 真实模型调用只通过单独的手动冒烟检查验证，且必须使用本地 `.env` 或运维环境变量提供密钥。
