# Bug 修复与优化最小改动方案

> 日期：2026-06-29
> 范围：Bug1-Bug6 的最小改动方案与验收测试说明
> 原则：不推翻现有权限模型，不新增复杂后台模块，不保存员工答题历史，不引入非 MVP 依赖。

## 总体目标

本轮优先解决已暴露的真实可用性问题，并用小范围增强降低后续运营成本：

1. 重置密码时必须给出明确校验提示。
2. 内容分类从纯手输改为“固定分类 + 历史已用分类”的可选输入。
3. 长列表按固定条数分页或分段展示。
4. 最新必读可按分类、部门范围做轻量筛选。
5. 所有前端时间统一展示北京时间。
6. 巩固测试默认紧跟更新，同时保留复习旧内容能力。

## 非目标

- 不新增 `content_categories` 分类表。
- 不新增分类管理后台。
- 不把巩固测试升级成考试系统。
- 不新增员工答题记录、分数、排行、历史成绩表。
- 不改变现有 `admin/full_user/general_user` 与 `global/department` 权限规则。

## Bug1：重置密码按钮点击无反应

### 问题判断

当前后端已经要求密码至少 8 位，前端 `confirmReset` 也有长度判断，但错误提示复用了页面全局 `error`，重置面板附近没有稳定提示，用户容易感觉“点了没反应”。

### 最小改动方案

- 在 `frontend/src/pages/admin/UsersPage.vue` 增加独立状态 `resetError`。
- 重置密码面板输入框增加：
  - `minlength="8"`
  - `maxlength="128"`
  - 可选：`autocomplete="new-password"`
- 点击确认时：
  - 空密码：显示“请输入新密码”。
  - 少于 8 位：显示“新密码至少 8 位”。
  - 后端返回 422：显示后端错误或统一文案“新密码至少 8 位”。
- 打开重置面板、取消重置、重置成功时清空 `resetError`。

### 验收测试

1. 管理员进入账号管理。
2. 点击某个员工账号的“重置密码”。
3. 输入 `1234567`，点击“确认重置”。
4. 页面应在重置面板附近显示“新密码至少 8 位”。
5. 不应弹出成功提示，不应调用成功后关闭面板。
6. 输入 `NewPass@2026`，确认重置。
7. 页面显示重置成功提示，重置面板关闭。
8. 使用该员工账号和新密码登录，登录成功。

## Bug2：新建内容分类改为可选输入

### 采用方案

采用“固定分类 + 从已有内容中读取已用分类”的稍好版。

分类仍复用现有字段：

```text
contents.category
```

不新增数据库表，不新增分类 ID，不迁移历史数据。

### 字段边界

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `category` | 内容业务分类，用于内容组织和筛选 | 价格口径、风控口径、银行合作、储能业务 |
| `scene` | 标准化话术的具体使用场景 | 客户质疑收益率时、银行初次拜访时 |
| `department` | 权限范围，决定哪些部门账号可见 | A 部门、银行团队、储能事业部 |

分类不等于部门，也不等于场景。

### 后端最小改动

新增管理员接口：

```text
GET /api/admin/content-categories
```

返回示例：

```json
{
  "items": ["价格口径", "风控口径", "银行合作", "回款催收"]
}
```

接口规则：

- 仅管理员可调用。
- 从 `contents.category` 查询历史已用分类。
- 去掉前后空格。
- 过滤空值。
- 去重。
- 最多返回 100 个。
- 推荐按最近更新时间倒序排序，让最近使用的分类靠前。

### 前端最小改动

新增固定分类常量，例如：

```text
价格口径
风控口径
银行合作
储能业务
售后问题
客户异议
产品介绍
合规边界
合同条款
回款催收
```

在 `frontend/src/pages/admin/ContentEditorPage.vue`：

- 页面加载时调用 `GET /api/admin/content-categories`。
- 将固定分类和历史分类合并去重。
- 分类字段改为“可输入的下拉建议”：
  - 优先使用当前原生表单风格的 `input + datalist`。
  - 管理员可以从建议里选，也可以输入新分类。
- 保存内容时仍提交字符串 `category`。

### 验收测试

1. 管理员登录后台。
2. 已有内容中存在分类 `回款催收`。
3. 打开新建内容页。
4. 分类输入框应能选择固定分类，例如 `价格口径`。
5. 分类输入框也应能选择历史分类 `回款催收`。
6. 输入一个新分类 `并网流程` 并保存草稿。
7. 内容保存成功，内容列表显示分类 `并网流程`。
8. 再次打开新建内容页，`并网流程` 应出现在分类建议中。
9. 通用员工、完整权限员工调用 `/api/admin/content-categories` 应被拒绝。

## Bug3：数据变多后列表拉长

### 问题判断

后台内容管理已有分页。账号管理、测验题管理、大更新专题测验包接口已有分页能力，但部分前端页面没有展示分页控件。员工端最新必读、标准话术当前一次性展示全部可见内容。

### 最小改动方案

后台：

- 账号管理复用 `GET /api/admin/users?page=&page_size=`，补分页状态和“上一页 / 下一页”控件。
- 测验题管理复用 `GET /api/admin/quiz-questions?page=&page_size=`，补分页状态和控件。
- 大更新专题测验包复用 `GET /api/admin/quiz-sets?page=&page_size=`，单独维护专题包分页状态。
- 默认每页 10 或 20 条，建议后台保持 20 条。

员工端：

- 最新必读先加前端分页，每页 10 条。
- 标准话术先加前端分页或分组内“查看更多”，每组默认展示最新 10 条。
- 若后续内容量明显增大，再把员工端列表分页下沉到后端接口。

### 验收测试

1. 准备超过 25 个账号。
2. 账号管理首页只显示第一页固定条数。
3. 点击下一页后显示后续账号，页码和总数正确。
4. 准备超过 25 道测验题。
5. 测验题管理首页只显示第一页固定条数。
6. 点击下一页后显示后续题目。
7. 准备超过 15 条最新必读。
8. 员工端最新必读默认只显示第一页 10 条，可翻页查看后续内容。

## Bug4：最新必读按部门和场景分类

### 最小改动方案

不新增字段，复用现有数据：

- 分类：复用 `category`。
- 部门范围：复用 `scope_type` 和 `department_name`。

员工端最新必读列表增加轻量筛选：

- 分类筛选：全部 + 当前可见内容中出现过的分类。
- 可见范围筛选：全部、全公司通用、本部门。

管理员后台内容列表已有分类、权限、状态筛选，可暂不新增更多复杂筛选。

### 验收测试

1. 管理员创建并发布多条最新必读：
   - 全公司通用 + 价格口径
   - 本部门 + 风控口径
   - 其他部门 + 任意分类
2. A 部门员工登录最新必读。
3. 页面只出现全公司通用和 A 部门可见内容。
4. 选择分类 `价格口径`，只显示该分类的可见内容。
5. 选择“本部门”，只显示当前员工部门限定内容。
6. 其他部门内容不应通过筛选泄露。

## Bug5：时间显示没有使用北京时间

### 问题判断

当前前端 `formatDateTime` 只是把字符串中的 `T` 替换为空格并截断，没有做时区转换。后端用 UTC 存储是合理的，但前端展示必须统一转成北京时间。

### 最小改动方案

修改 `frontend/src/utils/format.ts`：

- 使用 `Intl.DateTimeFormat('zh-CN', { timeZone: 'Asia/Shanghai' })`。
- 输入为空返回 `-`。
- 输入无法解析时返回 `-` 或原始值，建议返回 `-`，避免展示瞎编时间。
- 所有页面继续复用 `formatDateTime`，不逐页单独处理。

建议格式：

```text
2026/06/29 18:30
```

或保持现有风格：

```text
2026-06-29 18:30
```

以实现时统一为准。

### 验收测试

1. 构造接口时间 `2026-06-29T10:30:00Z`。
2. 前端应显示北京时间 `2026-06-29 18:30`。
3. 最新必读、话术详情、AI 来源、账号管理、部门管理、测验题管理、未命中问题页面都应使用同一格式。
4. 空时间显示 `-`。
5. 非法时间不应显示“瞎编”的当前时间。

## Bug6：巩固测试显示策略

### 平衡目标

巩固测试既要让员工紧跟最新更新，也要允许员工主动复习旧内容。

采用“双模式”：

| 模式 | 默认 | 目标 | 出题策略 |
| --- | --- | --- | --- |
| 跟进最新 | 是 | 紧跟最近更新内容 | 大更新专题题优先，中更新复核题优先，最近发布内容关联题优先 |
| 复习旧内容 | 否 | 主动巩固旧知识 | 当前权限内所有有效题中抽取，可按分类筛选 |

### 后端最小改动

扩展员工测验接口：

```text
GET /api/app/quiz?mode=latest
GET /api/app/quiz?mode=review
GET /api/app/quiz?mode=review&category=价格口径
```

规则：

- 默认 `mode=latest`，兼容现有调用。
- `latest`：
  - 仍只返回启用、审核通过、无需复核、未过期、当前用户可见题目。
  - 排序优先使用现有 `priority desc`。
  - 同等优先级下，优先关联内容发布时间更近的题。
  - 题目不足时用普通有效题补足。
- `review`：
  - 在当前用户权限范围内取所有有效题。
  - 可按关联内容 `category` 过滤。
  - 排序可使用 `updated_at desc` 或稳定轮换；本轮最小实现建议先用稳定排序。

### 前端最小改动

在 `frontend/src/pages/app/QuizPage.vue`：

- 增加模式切换：
  - 跟进最新
  - 复习旧内容
- 复习旧内容模式下展示分类筛选。
- 显示答题进度：`已答 N / 共 X 题`。
- 未答完时：
  - 禁用提交，或点击提交时提示“请先完成所有题目”。
  - 建议最小实现为点击提交时提示，不强制禁用按钮。
- 提交后：
  - 禁用选项，避免结果展示后继续改答案造成误解。
  - 展示每题对错、正确答案、解析、关联话术入口。
- 增加“重新抽题”按钮，重新加载当前模式题目并清空答案和解析。

### 验收测试

1. 管理员创建并发布一条大更新内容，生成或手动创建关联高优先级题。
2. 管理员创建旧内容关联题和普通题。
3. 员工进入巩固测试，默认模式为“跟进最新”。
4. 默认题目中应优先出现大更新或最近更新关联题。
5. 切换到“复习旧内容”。
6. 页面能展示当前权限内旧题。
7. 选择某个分类后，只出现该分类关联内容的题。
8. 未答完点击提交，应提示“请先完成所有题目”。
9. 答完提交后，显示解析并禁止继续改选。
10. 点击“重新抽题”，答案和解析清空，重新加载题目。
11. 通用权限员工不应看到全量级题或其他部门题。
