# 部门范围权限实施计划

## 目标

基于 `docs/department-scope-permission-design.md`，在现有“账号等级 + 内容等级”权限模型上增加单部门范围控制：

- 账号可绑定一个归属部门。
- 内容可选择“全公司通用”或“限定部门”。
- 员工端、AI 检索、巩固测试都必须同时满足部门范围与账号等级过滤。
- 管理员仍为全局管理员，不做部门管理员、部门树、多部门授权。

## 实施边界

本次实现：

- 新增部门数据模型和后台部门管理接口。
- 为用户、内容、发布版本、内容切片增加部门范围字段。
- 内容发布时把可见范围快照写入版本和切片。
- 员工内容列表/详情、RAG 向量召回、MySQL 关键词召回、MySQL 回查、测验抽题全部应用部门过滤。
- 前端后台支持维护部门、给员工选择部门、给内容选择可见范围。
- 员工端展示“可见范围 / 权限等级 / 更新级别”。

本次不实现：

- 多部门账号。
- 部门树和上下级穿透。
- 部门管理员。
- 内容多部门可见。
- 未绑定内容的手工题独立部门范围字段。

## TDD 验收用例

先补红灯测试，再实现代码：

1. 管理员可创建、编辑、停用、启用部门。
2. 限定部门内容必须选择启用部门；全公司通用内容不能带 `department_id`。
3. A 部门员工能看到全公司通用内容和 A 部门内容。
4. A 部门员工不能看到 B 部门内容。
5. `general_user` 即使部门命中也不能看到 `full` 内容。
6. `full_user` 能看到本部门 `general + full` 内容以及全公司通用 `general + full` 内容。
7. 无部门员工只能看到全公司通用内容。
8. AI 问答的 MySQL 关键词召回与最终回查不能命中其他部门内容。
9. Milvus 元数据过滤包含部门范围字段。
10. 巩固测试不能抽到其他部门绑定内容的题。
11. 历史版本能保留发布时的范围快照。

## 实施步骤

### 1. 数据层

- 增加 `departments` 表。
- `users` 增加 `department_id`。
- `contents`、`content_versions`、`content_chunks` 增加 `scope_type` 和 `department_id`。
- 迁移现有内容为 `scope_type = global`，现有用户 `department_id = NULL`。

### 2. 后端权限工具

- 保留现有账号等级过滤。
- 增加统一部门范围过滤函数：
  - `global` 内容全员按等级可见。
  - `department` 内容仅当前用户 `department_id` 命中时可见。
  - 无部门员工不能命中任何部门限定内容。
  - 管理员后台仍可看全量。

### 3. 后台接口

- 部门管理接口。
- 用户创建/编辑返回并接收 `department_id`。
- 内容创建/编辑返回并接收 `scope_type`、`department_id`。
- 发布、历史版本、切片生成写入范围快照。

### 4. 员工端与 AI/测验

- 员工内容列表/详情增加部门过滤。
- RAG 向量召回元数据增加范围字段，MySQL 关键词召回和最终回查重复过滤。
- 测验抽题与提交校验时，绑定内容题跟随关联内容当前可见范围。

### 5. 前端

- 后台新增部门管理入口。
- 用户管理显示/编辑归属部门。
- 内容管理显示/编辑可见范围，发布确认展示影响范围。
- 员工端内容和 AI 来源显示可见范围。

### 6. 验证与记忆

- 运行后端目标测试和前端测试。
- 更新 `memory-bank/architecture.md`，记录部门范围权限模型。
