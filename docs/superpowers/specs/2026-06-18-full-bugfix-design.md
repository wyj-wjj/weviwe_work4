# 企业话术智能检索系统全量 Bug 修复设计

## 目标

在不改变 MVP 架构和权限模型的前提下，修复 `修bug_prompt.md` 中列出的十类问题，并建立可重复的后端、前端和浏览器回归覆盖。

本次工作保持以下边界：

- FastAPI 单体后端不拆分。
- MySQL 继续作为唯一权威业务数据源。
- Milvus 仅保存索引和过滤元数据。
- AI 回答前继续从 MySQL 回查正文和权限。
- 通用员工不得查看、召回、引用或通过来源获知全量级内容。
- 不新增对话历史、测验成绩、统计看板等非 MVP 能力。

## 已确认的现场证据

- 快速连续提交“质保期、回收期、并网要求”后，页面问题为“并网验收新要求？”，回答却为投资回收期内容。
- “客户对价格有异议怎么处理？”对应内容在 MySQL、当前 chunk 和 Milvus 索引中均有效，但真实向量分数约为 `0.673906`，低于全局阈值 `0.7`。
- 当前标准化话术 chunk 包含场景、推荐说法、禁用说法和注意事项，但不包含标题、分类和摘要；价格关键词只存在于摘要中。
- 基础话术 chunk 只包含正文，结构化 `points` 中的 IRR、收益构成等事实没有进入检索和生成上下文。
- 通用与完整员工都按 `QuizQuestion.id ASC LIMIT 10` 获取题目。真实库前十道均为旧通用测试题，因此完整员工永远拿不到全量题。
- 真实库存在 Phase45、阶段 8 和 `??` 乱码测试数据，影响分页、抽题和验收判断。
- 测验结果链接固定生成 `/app/scripts/{id}`，没有关联内容类型契约。
- 发布接口每次调用都会创建版本；数据库唯一约束只能避免相同版本号，并不能表达“同一草稿只发布一次”的业务幂等性。
- DashScope 调用把连接错误统一映射成不可重试响应错误；调查过程中真实遇到过 SSL 连接瞬时中断。
- Chrome 当前未运行，当前 Chrome 配置也未检测到 Codex Chrome Extension；应用内浏览器可以正常访问本地站点。

## 方案选择

### 采用方案：定向一致性修复

通过小范围数据契约补充和服务层不变量修复根因：

- 前端请求隔离使用取消信号和请求序号。
- RAG 检索文本补齐标题、分类、摘要及结构化字段。
- 对少量明确中文口语短问句做确定性查询扩展，不降低全局阈值。
- 测验抽题保证权限正确且完整员工在存在全量题时至少获得一道全量题。
- 发布增加草稿修订标识和已发布修订标识，后端负责幂等。
- 外部服务仅对明确临时错误有限重试。
- 提供只识别已知测试数据、默认 dry-run 的清理命令。

### 未采用：只修前端

只修前端可以解决串答、复制和发布双击，但无法保证 API 重复提交、测验权限抽题、RAG 召回和真实数据污染，因此不能满足验收。

### 未采用：全局降低相似度阈值

把阈值降至价格异议分数以下会扩大天气、股票等无关问题误命中的风险，也无法解决短问句和上下文字段缺失的根因。

## 详细设计

### 1. AI 请求并发隔离

`askRag` 接受可选 `AbortSignal` 并传给 Axios。`AiAnswerPage` 为每次问题变化创建新的 `AbortController`，在下一次请求和组件卸载时取消旧请求，同时维护单调递增请求序号。

只有序号仍为最新且请求未取消时，响应才能写入 `answer` 和 `state`。新请求开始时立即清空旧回答和来源。取消错误不显示服务异常；旧请求的成功或失败都不能覆盖新请求。

员工端提问按钮在路由已经指向相同规范化问题时不重复导航；不同问题仍允许快速切换，由结果页负责隔离。

### 2. RAG 检索文本与短问句召回

索引文本按内容类型生成带字段名的稳定文本：

- 通用前缀：标题、分类、摘要。
- 基础话术：正文及结构化要点 `points`。
- 标准化话术：场景、推荐说法、禁用说法、注意事项。
- 最新必读：更新正文及调整要点。

字段顺序固定，以保证内容 hash 和重建索引可预测。权威正文仍来自不可变 `ContentVersion`。

查询扩展仅处理明确、可审计的中文口语表达，例如“电池能用多少次”扩展为“电池循环寿命、充放电循环次数”。扩展后的文本只用于 embedding；原始问题仍用于回答生成和未命中记录。全局阈值保持 `0.7`。

发布后和重试索引均使用新文本。现有真实内容通过管理员重试索引或维护命令重新生成当前版本索引，不创建新内容版本。

### 3. 上下文与来源相关性

MySQL 回查继续验证：

- 内容已发布。
- chunk 为 active。
- chunk 属于当前版本。
- 内容权限属于当前用户可见集合。

候选按 Milvus 分数降序处理。相同内容的多个 chunk 合并为一个上下文，来源与实际传入模型的上下文一一对应。使用相对分数窗口剔除明显弱于首个有效候选的来源，同时所有来源仍必须达到绝对阈值。

生成提示词要求优先直接回答问题，并覆盖来源中与问题直接相关的数字、条件和限制；不得机械罗列无关技术路线。基础话术的 `points` 进入上下文后，回收期回答可以包含来源已有的 IRR 和收益测算信息。

### 4. 权限冲突契约

“电池能用多少次？”的 `6000-8000 次`来自全量级技术路线内容，因此验收改为由 `es_full` 执行。`es_general` 对该全量内容的列表、详情、Milvus 候选、MySQL 回查和来源返回继续全部拒绝。

不复制全量技术路线到通用内容，也不调整现有权限。

### 5. Clipboard 降级

复制流程：

1. 若 `navigator.clipboard.writeText` 可用，优先调用。
2. API 不存在或拒绝时，创建屏幕外临时 `textarea`，保存当前焦点和选择区，选中文本并调用 `document.execCommand('copy')`。
3. 无论成功失败都移除临时 DOM，并恢复原焦点和选择区。
4. 两种方式均失败时显示失败反馈，并保留 rejected Promise 的显式处理。

该组件继续服务推荐说法、完整话术和 AI 回答三类入口。

### 6. 测验抽题与关联内容

员工测验响应仅包含启用且当前用户可见的题目。

抽题策略：

- 通用员工从通用级题目中稳定选取最多 10 道。
- 完整员工在存在启用全量题时，先稳定选择至少 1 道全量题，再用通用级和剩余全量题补足到最多 10 道。
- 总数不足 5 时返回实际可用数量；数据准备和验收夹具保证正常环境有 5 至 10 道。

测验题和提交结果增加：

- `related_content_type`
- 仅在关联内容已发布、当前版本存在且用户有权访问时返回关联 ID 和类型。

无权限、已下线或不存在的关联内容都返回空关联，不渲染链接。前端复用 `sourceDetailPath` 生成 `must_read` 或 script 路径。

### 7. 内容发布幂等与版本不变量

新增内容草稿修订字段：

- `draft_revision`：创建时为 1，每次有效草稿修改递增。
- `published_draft_revision`：最近一次成功发布的草稿修订号，未发布时为空。

发布流程在数据库事务内锁定内容行：

1. 校验内容未下线。
2. 若 `published_draft_revision == draft_revision`，返回当前版本，不新增版本和 chunk。
3. 计算并创建下一个版本。
4. 设置当前版本、状态和已发布修订号。
5. 失活旧 chunk，创建当前版本 chunk。
6. 提交后执行现有同步索引流程。

`ContentVersion` 增加权限级别快照，员工当前可见性仍以后端当前内容权限为准；历史版本页面显示发布时快照。

前端为每个正在发布、下线或重试索引的内容维护 pending 状态，按钮禁用，取消确认不产生 API 请求。前端 pending 只改善交互，后端修订幂等是最终一致性边界。

### 8. DashScope 临时错误重试

HTTP 客户端错误分类：

- 可重试：超时、连接错误、连接重置、HTTP 429、HTTP 500/502/503/504。
- 不可重试：配置缺失、401/403、其他 4xx、无效 JSON、缺失字段和非法响应。

每次请求最多 3 次尝试，使用短指数退避。重试封装位于单次外部 HTTP 调用内部，因此不会重复写入未命中记录、版本、chunk 或其他业务副作用。

日志只记录操作类型、模型、尝试次数、状态码和标准化错误类别，不记录 Authorization、API Key 或完整敏感请求头。

### 9. 测试数据与 UTF-8

保留自动化 E2E 的独立 SQLite 和进程内假客户端。

开发种子脚本改为：

- UTF-8 源文件和明确中文常量。
- 通过稳定 seed key、标题前缀或账号前缀幂等识别自身数据。
- 更新已有种子记录而不是重复新增。
- 同时创建可区分的通用题和全量题。

新增测试数据审计/清理命令：

- 默认只输出 dry-run 报告。
- 仅识别已知 Phase45、阶段 8、E2E、明确乱码签名和指定测试账号。
- 必须显式传入执行参数才删除。
- 不删除无法明确归属的业务数据，不重建数据库。
- Milvus 清理只处理被确认测试内容对应的 content ID。

### 10. 浏览器与自动化验收

Vitest 新增竞态、旧错误覆盖、取消、Clipboard 降级、关联类型路径和发布 pending 测试。

pytest 新增索引文本、查询扩展、权限回查、来源一致性、测验抽题、关联可见性、发布幂等、重试分类及种子幂等测试。

Playwright 扩充确定性夹具，覆盖：

- 快速连续 AI 提问。
- 通用员工全量内容零泄露。
- 完整员工循环寿命命中。
- 价格异议命中。
- 三种复制入口。
- 通用和完整员工测验差异。
- 最新必读与话术关联链接。
- 草稿、发布、重复发布、再发布、历史和下线。

应用内浏览器用于真实 MySQL/Milvus/DashScope 关键链路复验。Chrome 验收依赖用户安装并启用 Codex Chrome Extension；若环境仍不可用，将明确记录为环境阻塞，不能用其他工具冒充 Chrome 验证。

## 数据库迁移

新增一条 Alembic 迁移：

- `contents.draft_revision`，非空，默认 1。
- `contents.published_draft_revision`，可空。
- `content_versions.permission_level`，非空。

迁移时：

- 现有内容的 `draft_revision` 设为 1。
- 已发布且存在当前版本的内容将 `published_draft_revision` 设为 1。
- 历史版本权限快照用迁移时对应内容的权限回填；这是对旧数据的最佳可用快照，后续版本使用发布时真实权限。

升级、降级和 SQLite 测试迁移都需要覆盖。

## 验证顺序

1. 每类 Bug 先增加最小失败测试并确认失败原因。
2. 实施单一最小修复并运行定向测试。
3. 运行相关后端或前端测试。
4. 运行全部 pytest、Vitest、生产构建和 Playwright。
5. 通过应用内浏览器复验真实关键链路。
6. 若 Chrome 扩展可用，再完成 Chrome 第二轮验收。
7. 更新 `memory-bank/architecture.md`、`docs/测试prompt.md` 和种子/清理文档。

## 完成判定

- 快速连续提问不再串答。
- 价格异议命中 L-A-C-T，天气和股票仍未命中。
- 通用员工不能命中全量循环寿命；完整员工可以。
- 三类复制入口在真实浏览器可用。
- 测验按权限抽题，完整员工可稳定获得全量题，乱码种子不再生成。
- 关联内容路径和权限正确。
- 保存草稿不生成版本；同一草稿重复发布不增加版本；新草稿再发布只增加一个版本。
- 临时 DashScope 错误有限重试，不可重试错误立即失败。
- 测试清理默认 dry-run 且不影响未知业务数据。
- 全量自动化和真实浏览器关键链路通过，或对外部环境阻塞给出具体证据。
